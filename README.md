# 每日運動紀錄 Fitness Record

把**訓練和飲食放在同一個地方看**的個人健身紀錄工具。給我和另一半兩個人每天使用，由我擔任產品經理，與 AI 協作從需求、設計、開發、資安檢查一路做到上線。

- **線上版**：https://daniellllin.github.io/fitness-record/
- **示範版（免登入、資料為虛構）**：https://daniellllin.github.io/fitness-record/demo/
- **作品介紹**：https://daniellllin.github.io/fitness-record/showcase/

---

## 要解決的問題

1. **資料散在好幾個地方，看不出彼此的關係。** 重訓記在筆記、跑步在 Strava、體重在 Apple 健康、飲食在另一個 App。想回答「這週練了多少、吃了多少、體重有沒有往目標走」，要在好幾個 App 之間切換，自己心算。
2. **市售 App 各管一塊。** 想把訓練、飲食、身體數據整合在一起，通常要訂閱好幾個服務，資料也存在別人的伺服器上。
3. **台灣的食物不好記。** 國外的營養資料庫查不到台灣常吃的便當、小吃和在地包裝食品，記錄不準就沒有參考價值。
4. **記錄太麻煩就不會持續。** 重訓一組一組輸入、每餐查營養素，只要多幾個步驟就容易放棄。

## 核心目標

| 目標 | 怎麼衡量做到了 |
|---|---|
| **訓練與飲食同等重要，放在一起看** | 首頁同時顯示今天吃了多少、目標多少、今天有沒有運動；週報把訓練負荷、熱量差和體重變化放在同一頁 |
| **資料自己擁有** | 運動紀錄存在使用者自己的 Google 雲端硬碟；飲食與身體數據存在自架的 SparkyFitness |
| **幾乎零成本** | 靜態網頁＋免費額度的服務，固定支出只有 SparkyFitness 主機 |
| **記錄要快** | 重訓自動帶入上次重量；飲食可以拍照、上傳照片、掃條碼、搜尋食藥署資料 |
| **安全與隱私** | 金鑰不放在瀏覽器、登出會清除裝置資料、跨帳號存取實測過 |

## 開發歷程

每個階段都先在測試版（`/beta/`）實際使用，確認沒問題才升級正式版。

### M1　能每天用的運動紀錄

**問題**：先要有一個每天願意打開的記錄工具，而且不想架伺服器、不想付費。
**做法與決策**
- 單一 HTML 檔放在 GitHub Pages，不需要建置流程。
- 紀錄存在使用者自己的 Google 雲端硬碟（App 專用隱藏區 `appDataFolder`）。沒有自己的資料庫，開發者也讀不到任何人的資料；只用非敏感的授權範圍，不需要 Google 審查。
- 重量訓練逐組輸入，**自動帶入上次的重量與次數**；內建動作教學。
- 支援離線：每台裝置有自己的快取，跨裝置以紀錄 id 合併、刪除以墓碑同步。

### 設計改版：從能用到好用

**問題**：功能可以用，但版面是工程師排的，手機和電腦都不順手。
**做法與決策**
- 先在 Claude Design 做出設計稿，再套到 App：使用裝置內建字體（不載入網路字型，開啟更快），同步狀態放在右上角。
- 動作庫改用公有領域的 free-exercise-db，約 870 個動作，附起始與結束示範圖。
- 桌機版：960px 以上改成左側導覽＋兩欄。

### M2　符合實際的訓練型態

**問題**：實際的訓練不只重訓和跑步，還有 HYROX、高強度間歇、混合健身，也需要看出「這週練得太多還是太少」。
**做法與決策**
- HYROX 八個站點與模擬賽、間歇（回合／作息比）、混合健身（WOD 類型與成績）各有專屬欄位。
- 週報用 **session-RPE（時長 × 自覺強度）** 計算訓練負荷，和前幾週比較，並標出高強度日。
- 加入賽事：記下自己報名或關注的比賽。

### M3　公開賽事行事曆，第一次升級正式版

**問題**：想知道近期有哪些比賽可以報名，但資訊散在好幾個報名網站。
**做法與決策**
- GitHub Actions 每週一自動抓三個報名網站，去除重複後寫成 `data/races.json`，App 直接讀這個檔案，不需要後端。
- 遵守各網站的 robots.txt：有一個網站禁止抓取，就不納入。
- 賽事從底部分頁移到首頁入口，排序是「自己報名或關注的比賽優先，其次是近期公開賽事」。
- 線上路跑另外評估後決定先不做。
- 測試完成後，m3 成為第一個正式版。

### M4　飲食整合：把吃的也放進來

這是最大的一個階段，從選擇資料來源開始，前後經過 25 個測試版。

**1. 先用最低成本驗證**
- **問題**：飲食與營養分析要做得好很花時間，市面上已有成熟的開源工具。
- **決策**：採用自架的 **SparkyFitness** 管理飲食與身體數據，主機放在 PikaPods（之後打算移到自己的 NAS）。App 不直接連 Sparky，而是先建一個 **Cloudflare Worker 轉接程式**，用免費額度先驗證整合可不可行，再決定要做多深。
- **取捨**：Strava 要訂閱才能直接串，改走「Strava → Apple 健康 → Sparky iOS App」；原本評估的 AthleteKit 功能重疊，拿掉。

**2. 台灣的食物資料**
- 把衛福部食藥署的食品營養成分資料匯入 Sparky，搜尋時優先顯示。
- 評估過 FatSecret、Nutritionix，台灣食物收錄與授權條件都不適合，所以不採用。

**3. 拍照辨識**
- 照片縮小後交給 Gemini 辨識每一項食物與克數，再逐項對到食藥署資料，讓使用者確認後才寫入。
- 遇到「Gemini 不支援這個連線地區」的錯誤時，改由 Sparky 自己的 AI 服務辨識，名稱轉成中文後再對食藥署資料。

**4. 每日 TDEE 與階段目標**
- **問題**：固定的熱量目標無法反映「今天有沒有運動」。
- **決策**：每日 TDEE ＝ 基礎代謝 × 1.2 ＋ 當天運動消耗；階段目標分成慢慢減脂、減脂、維持、增肌，換算成每天的熱量差。運動日目標自動提高。
- App 記的訓練會以 MET 估算消耗寫進 Sparky；同一天如果已經有 Apple 健康的實測值，就不重複寫入。
- 蛋白質目標依體重計算（每公斤 1.6 g）。

**5. 版面重新設計**
- 用 Dieter Rams 的十項設計原則檢視介面，定出各頁的角色：首頁看今天與本週、統計看每週與長期、飲食負責記錄、我的放設定。
- 建立文字層級（頁標題、區段標題、內文、說明、註腳），統一各頁。

**6. 記錄更快、更不容易漏**
- 每一餐都可以回頭修改份量、換餐別或刪除。
- **掃條碼**：查自己存過的食物 → Open Food Facts → 查不到就拍營養標示，讓 AI 讀數字。存過的商品下次掃描會直接找到。
- 營養標示可選「每 100 公克」或「每一份」，切換時營養素自動換算。
- **先存起來，晚點再辨識**：網路不好或當下不方便時，照片連同日期與餐別存在這台裝置，7 天內補辨識。
- **上傳已拍的照片**：讀取照片的拍攝時間，自動記到拍照當時那一餐。

**7. 上線前的資安檢查**
- 依外部程式碼審查（Codex）的 P1–P3 項目逐一修正：
  - Sparky 金鑰不再放在瀏覽器：第一次連接時交給轉接程式加密保存，綁定 Google 帳號；App 只拿到 12 小時、只存在記憶體裡的工作階段。
  - 登出時先確認同步完成，再清除這台裝置的資料。
  - 拍照辨識設每人每分鐘、每天的使用次數上限。
  - 本機伺服器只接受本機連線，並擋下目錄穿越。
  - 匯出 CSV 時防止公式注入。
  - 補上個資使用說明。
- 用兩個帳號實測跨帳號存取，發現上游 Sparky 在 API 金鑰模式下，單筆運動紀錄沒有檢查擁有者；在轉接程式補上擁有者檢查。
- 撤銷金鑰後，幾秒內就無法再讀取資料（實測）。

**8. 升級正式版**
- 正式版與測試版各自使用一個轉接程式，轉接程式改版先在測試版驗證。
- 測試期間的真實紀錄合併進正式版；已寫進 Sparky 的運動消耗靠紀錄編號比對，不會重複。

```
             └──────┬───────────────────────────┬─────────────────────────────────┬──────────────────────┘
                    │ Google 登入                │ 工作階段（12 小時，只在記憶體）     │ 每週更新的靜態檔
                    ▼                           ▼                                 ▼
     Google 雲端硬碟 appDataFolder       Cloudflare Worker 轉接程式              data/races.json
     （運動紀錄，使用者自己的）           · 驗證 Google 登入、發工作階段          ▲
                                        · 加密保存 Sparky 金鑰（KV）            │ GitHub Actions 每週一

                                   食藥署食物庫、
                                   Open Food Facts
                                            ▲

```

## 技術重點

- **前端**：單一 HTML 檔、原生 JavaScript，沒有框架與建置流程；圖表是自製 SVG；淺色／深色主題；手機、平板、桌機三種版面。
- **登入與儲存**：Google Identity Services；Google Drive REST API（`drive.appdata`）；localStorage 依帳號分開快取；待辨識照片存在 IndexedDB。
- **轉接程式**：Cloudflare Workers ＋ KV；AES-GCM 加密保存金鑰（金鑰由 HKDF 衍生）、HMAC 簽章的工作階段；路徑、方法、欄位與數值範圍白名單。
- **條碼掃描**：html5-qrcode（Apache-2.0），放在同一個網站，按下掃描時才載入。
- **資料來源**：衛福部食藥署食品營養成分資料庫、Open Food Facts、free-exercise-db（公有領域）。

## 自行架設（只用運動紀錄的部分）

1. 到 Google Cloud Console 建立專案，啟用 Google Drive API。
2. 設定 OAuth 同意畫面，建立「OAuth 用戶端 ID → 網頁應用程式」，在「已授權的 JavaScript 來源」填入你的網域。
3. 把用戶端 ID 填進 `index.html` 開頭的 `CONFIG.CLIENT_ID`，或在登入畫面貼上。

完整圖文步驟見 [setup.html](setup.html)。飲食功能需要自架 SparkyFitness 與轉接程式，設定較多，這裡不列出。

本機執行：把 `index.html`、`啟動運動紀錄.bat`、`server.js`、`serve.py`、`serve.ps1` 放在同一個資料夾，雙擊 `.bat`，會開在 `http://localhost:8080`（Google 登入不接受直接開 `file://`）。
